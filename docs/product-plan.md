# Looproom 제품 기획: 핵심 기능 3가지

> 상세 기획(메뉴 구조도·서비스 구조도·기능 정의서·플로우·UX/UI·정책)은 [docs/README.md](README.md)에서 시작한다.

> 대상: 창업팀, 디자이너, 개발자
> 범위: ① 영상 업로드·피드백 ② 프로젝트 관리 + 데이터 대시보드 ③ AI 분석 리포트
> 원칙: 가짜 지표·후기 없이, 실제 사용 데이터가 쌓일수록 강해지는 제품

---

## 0. 한 줄 포지셔닝

**"댄스팀이 리허설 영상에 서로 피드백을 주고받고, 각자 자기 파트를 고치고, 그 기록이 시즌 내내 쌓이는 곳."**

> v2 포지셔닝: 처음에는 "코치 → 댄서" 한 방향 도구로 기획했지만, **팀원 누구나 서로 피드백하는 팀 도구**로 바꿨다. v3에서 역할을 **Owner(방장)·Member 둘**로 줄였다. 코치·강사도 멤버로 참여한다.

### 0-1. 왜 팀 구도인가

| | 코치 중심 (v1) | 팀 중심 (v2) |
|---|---|---|
| 고객 | 코치가 있는 팀만 | **크루·대학 동아리·커버 그룹·코치 있는 팀 모두** |
| 활성 사용자 | 코치 1명 (댄서는 주로 보기) | **팀원 전원**이 쓰고, 받고, 동의함 |
| 성장 | 코치 1명 → 댄서 초대 | 팀 단위 유입, 팀원이 다른 팀에도 소속 → **팀 간 전파** |
| AI 리포트 | 코치 한 사람 의견 요약 | 여러 명 의견의 **합의 신호** ("3명이 같은 부분 지적") |
| 결제자 | 코치 | 팀 공간 Owner (Team 플랜) |

**리스크와 대응**: 동료 피드백은 엇갈리거나 날카로울 수 있다 → 노트는 사람이 아니라 *순간*에 붙이기, 반복 대신 👍 동의, Owner의 정리(해결·숨김), 리캡에서 합의된 노트 우선 ([06-policy.md 1-4](06-policy.md)).

일반 영상 리뷰툴(Frame.io 등)은 *편집본 승인*에 최적화돼 있고, 팀 운영툴은 *일정·출석*에 최적화돼 있다.
Looproom은 그 사이, **"교정(correction)이 실제로 고쳐졌는가"** 를 추적하는 유일한 도구가 된다.

핵심 루프:

```
리허설 영상 업로드 → 팀원들이 순간·구간에 노트·스케치·멘션·👍 → 각자 자기 파트 반복 연습(루프·거울모드) → 다음 테이크 → 해결 확인
      ↑                                                                    │
      └──────────── 대시보드·AI 리포트가 다음 연습의 초점을 정해줌 ←──────────┘
```

North Star Metric: **주간 해결된 교정 수 (Corrections resolved / week)**
리뷰를 열심히 하는 게 아니라 "고쳐졌다"까지 가야 가치가 생기므로, 이 수치가 리텐션과 가장 직접적으로 연결된다.

## 1. 영상 업로드 및 피드백

### 1-1. 사용자 시나리오

| 사용자 | 기기 | 해야 하는 일 | 성공 기준 |
|---|---|---|---|
| 댄서 | 휴대폰 (90%+) | 영상 올리기, 피드백 보기, 해당 구간 연습, 다음 테이크 올리기 | 링크 클릭 → 피드백 확인까지 **3탭 이내**, 앱 설치 없음 |
| 코치 | 노트북 (리뷰) / 휴대폰 (확인) | 여러 댄서 영상 검토, 노트·스케치 남기기, 해결 처리 | 영상 1개 리뷰 **2분 이내**, 키보드만으로 가능 |

### 1-2. 기능 명세

**업로드**
- 카메라 롤에서 바로 업로드(MP4/MOV/WebM), **이어올리기(resumable, tus 프로토콜)**: 지하철에서 끊겨도 이어짐
- 업로드 중 화면 이탈 가능 + 완료 푸시/이메일
- 서버에서 HLS 변환(720p/1080p) + 썸네일 + 오디오 파형 추출 → 느린 네트워크에서도 즉시 재생
- 업로드 시 리뷰(요청)에 자동 연결 → "Take 2"로 이전 테이크과 묶임

**피드백 (코치)**
- 타임스탬프 노트 / **구간 노트**(00:42–00:48) / **스케치**(멈춘 프레임에 펜·원·화살표) / 음성 노트(30초)
- **레이블은 고르지 않는다**: 코치는 글만 쓰고, AI가 Timing · Pathway · Energy · Musicality · Technique로 자동 분류해 리포트·대시보드에서만 보여준다 (리뷰 속도 최우선)
- **@멘션**: 프로젝트에 초대된 공동 코치·어시스턴트·댄서를 노트에서 호출
- **구간 반복**: 노트를 누르면 그 순간으로 이동, 구간 노트는 그 부분만 반복 재생
- **교정 라이브러리**: 자주 쓰는 피드백 저장 → `/`로 불러오기 (락인 요소, 3장 참고)
- 상태: Open → Practicing(댄서가 연습 중) → Resolved(다음 테이크에서 확인됨)
- 키보드: `Space` 재생, `J/K/L` 탐색, `,` `.` 프레임 단위 이동, `N` 노트, `D` 스케치, `M` 거울모드, `[` `]` 구간 지정

**연습 (댄서)**
- 노트 탭 → 해당 순간으로 이동 → **구간 루프** + 0.25/0.5/0.75× 속도 + **거울모드**
- 루프 횟수·연습 시간 자동 기록 → 대시보드의 "연습 신호"가 됨
- 노트에 답글, "연습했어요" 체크, 다음 테이크 올리기 버튼이 같은 화면에

**테이크 비교**
- Take 1 | Take 2 나란히 보기, 같은 카운트 기준으로 싱크
- 노트는 다음 테이크으로 따라감 → 코치는 "해결됨" 한 번으로 마무리

### 1-3. UX 원칙
1. **댄서는 계정 없이 시작**: 초대 링크 → 이름 입력 → 바로 피드백 열람 (이메일 인증은 나중에)
2. **빈 화면 없음**: 첫 로그인 시 샘플 리뷰가 열려 있고, 노트 하나 남기는 것까지 안내
3. **모바일 우선**: 댄서 화면의 모든 버튼은 엄지 영역, 영상은 세로 영상도 꽉 차게
4. **실패 안내**: 업로드 실패 시 "이어올리기" 버튼, 용량 초과 시 압축 안내

## 2. 프로젝트 관리 + 데이터 대시보드

### 2-1. 프로젝트 (노션 같은 워크스페이스)

노션의 유연함은 가져오되, **댄스에 맞게 이미 짜여진 구조**로 시작하게 한다. 빈 페이지에서 시작하게 하지 않는다.

**구조**

```
Workspace (코치 / 스튜디오)
 └─ Project (쇼케이스 2026, 주간 수업, 대회 준비…)
     ├─ Overview      : 목표, 일정, 참여 댄서, 음악
     ├─ Count sheet   : 8카운트 단위 구간표 (구간·카운트·포커스·기준 영상·상태)
     ├─ Videos board : To submit → In review → Practicing → Fixed (칸반, 상태 자동)
     ├─ Pages         : 자유 문서 (블록 에디터, @멘션으로 노트·영상·댄서 연결)
     └─ Calendar      : 리허설·마감일
```

**핵심 기능**
- **템플릿**: 주간 수업 / 쇼케이스 / 대회 준비 / 오디션 준비 / 1:1 레슨 → 5분 안에 프로젝트 셋업
- **카운트 시트**: 음악 BPM을 넣으면 영상 타임라인에 8카운트 눈금 표시 → 노트가 "Verse 3×8, count 5"처럼 카운트로 표기됨 (댄서의 언어로 말하기)
- **같은 데이터, 여러 보기**: 리뷰를 표 / 보드 / 캘린더 / 댄서별로
- **@멘션 링크**: 문서 안에서 `@00:18 노트`, `@Maya Take 2` 연결 → 클릭 시 영상 해당 순간 재생
- 권한: **Owner(방장) / Member** 두 역할 + Guest(학부모·심사위원, 보기만). 리더·코치 역할 없음

### 2-2. 대시보드에 쓰는 데이터

"댄서가 춤출 때 측정되는 데이터"는 정확도와 신뢰가 중요하므로 **3단계로 나눠서**, 확실한 것부터 쌓는다.

| 단계 | 데이터 | 수집 방법 | 정확도 | 출시 |
|---|---|---|---|---|
| **A. 연습 신호** | 제출 횟수·마감 준수, 구간 루프 횟수, 연습 시간, 재생 위치 | 앱 사용 로그 (자동) | 높음 | MVP |
| **B. 피드백 신호** | 카테고리별 노트 수, 해결률, **해결까지 걸린 테이크 수**, 반복되는 교정 | 코치 노트 (자동) | 높음 | MVP |
| **C. 동작 신호 (Beta)** | **박자 대비 타이밍 오차(ms)**, 동작 크기(팔·다리 뻗음), 좌우 대칭, 테이크 간 일관성 | 영상 포즈 추정(MediaPipe 등) + 음악 비트 검출 | 중간 → 검증 필요 | Phase 3, 옵트인 |

C단계 원칙:
- 기본은 **꺼져 있음**. 워크스페이스 단위로 켬, 미성년자는 보호자 동의 필요
- 점수(랭킹)로 사람을 평가하지 않음. **"지난 테이크 대비 변화"** 만 보여줌
- 오차 범위를 함께 표기하고, 화면에 "Beta" 표시

### 2-3. 대시보드 화면

**코치용 (그룹 단위)**
- KPI: 해결된 교정 수 / 평균 해결 테이크 수 / 제출률 / 루프 연습 횟수 / (Beta) 박자 오차 추이
- **반복 교정 탐지**: "Late on the 'and' counts — 4명, 3주 연속" → 다음 수업 주제로 바로 이어짐
- 카테고리 추이: Timing 노트가 줄고 Musicality 노트가 늘면 = 팀이 다음 단계로 가는 중
- 댄서 × 주 히트맵: 누가 멈춰 있는지 한눈에 (조용히 뒤처지는 댄서 발견)

**댄서용 (개인)**
- 내 오픈 노트, 이번 주 할 일, 해결한 교정 기록("이만큼 늘었다")
- 비교·순위 없음. 내 과거와만 비교

**스튜디오용 (Studio 플랜)**
- 코치별·반별 활동, 학부모용 월간 성장 리포트 PDF (학원 재등록률에 직결 → 결제 이유)

## 3. AI 분석 리포트

### 3-1. 원칙: "요약하되, 지어내지 않는다"

AI가 춤을 직접 평가하지 않는다. **팀원이 남긴 피드백만** 근거로 정리한다.

- 모든 문장에 **출처 노트 링크**(각주) → 클릭 시 영상의 그 순간 재생
- 근거 노트가 없는 내용은 생성 금지 (구조화 출력 + 근거 ID 검증)
- 레이블(Timing 등)은 AI가 붙이고, 노트를 쓰는 사람은 고르지 않는다
- 받는 사람의 언어로 자동 번역

### 3-2. 하나의 기능: AI Recap

> v3 결정: "댄서 셀프 리포트"와 "코치 리포트"를 **AI Recap 하나로 통일**했다. 누구나 만들 수 있고, 범위만 고른다. 검토·발송 단계는 없앴다.

| 항목 | 내용 |
|---|---|
| 생성 단위 | **프로젝트 × 기간**. Video 하나로 좁히는 필터는 선택. 테이크 하나 단위 요약은 만들지 않음 (Video 화면에는 AI 없는 테이크 비교 요약) |
| 누가 만드나 | **프로젝트 멤버 누구나**, 원할 때 언제든 |
| 범위 | **Just me** (나에게 온·멘션된 노트) / **Whole project** (그 프로젝트의 모든 Team 노트) |
| 기간 | Last rehearsal · This week · This month · Custom |
| 공개 | 만든 사람만 보임 → **Share to project** 하면 프로젝트 피드에 올라감 |
| 보는 곳 | **프로젝트 › Recaps 탭**(본거지) · Home/Today 최근 리캡 카드 · Me › My recaps. 별도 메뉴 없음 |
| 보관 | **자동 저장**(날짜·범위). 같은 범위·기간은 테이크으로 접힘. 중요한 것은 📌 고정 (북마크 대신) |
| 자동 리캡 | 프로젝트 설정에서 켜면 매주 정해진 시간에 Whole project 리캡이 프로젝트에 자동 게시 (Owner 설정) |
| 학부모·외부 공유 | 리캡을 게스트 링크로 공유 (Studio) |

**왜 하나로 합쳤나**
- 역할이 Owner·Member 둘뿐이라 "코치만 보내는 리포트"가 필요 없다.
- 검토·발송 단계가 없으니 만들자마자 쓸 수 있다. 근거 인용이 신뢰를 대신한다.
- 리더가 있는 팀·학원은 Owner나 강사가 Whole project 리캡을 만들어 공유하면 같은 효과를 낸다.
- 화면·코드·요금제 모두 단순해진다.

**가드레일**
- 권한: 리캡에는 **만든 사람이 볼 수 있는 노트만** 들어간다 (Private take 노트는 그 사람에게 보일 때만).
- 근거 없는 문장 차단, 화면에 "AI summary of your team’s notes" 표시.
- 같은 범위·기간에 새 노트가 없으면 캐시 결과 반환, 플랜별 생성 횟수 제한.
- Just me 리캡의 할 일 체크 → 해당 노트 Practicing (연습 신호).
- 동의(👍)가 많은 노트, 여러 명이 지적한 내용을 먼저 보여준다 (합의 신호).

### 3-3. 리캡 활용 예

| 상황 | 범위 · 기간 | 누가 |
|---|---|---|
| 리허설 가기 전 내 할 일 확인 | Just me · Last rehearsal | 아무 멤버 |
| 이번 주 팀 전체 정리 공유 | Whole project · This week | 아무 멤버 (보통 방장) |
| 월말 성장 정리, 학부모 상담 | Just me 또는 Whole project · This month → 게스트 링크 | 멤버 본인 · 학원 강사 |
| 공연 직전 "아직 안 고쳐진 것" | Whole project · Custom (Keeps coming up 섹션) | 아무 멤버 |

### 3-4. 리포트 구조 (주간 예시)

```
Maya Chen · This week (Oct 19–25) · Built from 9 notes by Alex Lee
1. What you worked on   : Chorus timing, arm pathways in the transition [1][3]
2. What to do next      : ☐ Count "5-and-6" out loud through 00:18 [1]  ☐ ...
3. What landed          : ✓ Wider arm pathway at 00:42 (resolved in Take 2) [3]
4. Keeps coming up      : ⚠ Rushing the "and" counts — 3rd week in a row [1][5][8]
5. Focus for next week  : Musicality in the bridge (coach's note) [9]
```

### 3-5. 구현 메모
- 입력: 기간 내 노트(텍스트·AI 레이블·타임스탬프·상태·답글) + 프로젝트 맥락. 영상 자체는 넣지 않음 → 비용·개인정보 부담 낮음
- 출력: JSON 스키마(섹션별 문장 + source_note_ids) → 서버에서 ID 존재 여부 검증 후 렌더
- 비용: 주간 리포트 1건당 노트 수십 개 수준이라 저렴. Team 플랜 원가에 포함 가능
- 평가: 코치 수정률(얼마나 고쳐서 보냈나), 발송률, 댄서 열람률, 리포트 → 체크리스트 완료율

## 4. 락인과 해자 (Moat)

기능은 복제된다. **쌓이는 것**이 해자다. 단, 데이터를 인질로 잡는 방식(내보내기 차단)은 쓰지 않는다. 신뢰가 깨지면 글로벌 B2C·B2SMB에서 바로 이탈한다. 내보내기는 항상 열어 둔다.

| 레이어 | 무엇이 쌓이나 | 왜 떠나기 어려운가 |
|---|---|---|
| **1. 코칭 기억** | 댄서별 모든 테이크·노트·해결 기록 | 옮기면 "이 댄서가 어떻게 성장했는지" 맥락이 사라짐 |
| **2. 코치의 언어** | 교정 라이브러리, 코치가 고친 AI 레이블, 템플릿 | 코치의 코칭 방식 자체가 도구 안에 있음 |
| **3. 리포트 품질** | 기간이 길수록 풍부해지는 AI 리포트·대시보드 | 3개월 쓴 계정의 월간 리포트는 새 툴에서 재현 불가 |
| **4. 네트워크** | 댄서는 여러 코치·스튜디오에 속함. 댄서 프로필이 이동 | 댄서가 새 코치를 Looproom으로 초대 → 바이럴 루프 |
| **5. 습관** | 주간 다이제스트, 수업 전 코치 브리핑 | 매주 정해진 리듬으로 돌아옴 |
| **6. 데이터 해자 (장기)** | (옵트인) "순간 + 교정 + 음악"이 정렬된 데이터 | 댄스 특화 피드백 모델 학습 → 경쟁사가 가질 수 없는 데이터 |

성장 루프:
```
코치 가입 → 댄서 초대(무료) → 댄서가 피드백 경험 → 댄서가 다른 코치·팀에 링크 공유
→ 새 코치 가입 → …
```

## 5. 글로벌 SaaS 요건

- **다국어**: UI 영어/한국어/일본어/스페인어/포르투갈어부터. 노트·리포트 자동 번역
- **결제**: Stripe, 현지 통화 표시, 세금 자동 계산(Stripe Tax), 연간 결제 할인
- **개인정보**: 댄스 영상은 얼굴·신체가 담긴 민감 콘텐츠
  - 기본 비공개, 서명된 재생 URL(만료), 워크스페이스 단위 접근 제어
  - 영상·계정 삭제 즉시 반영, 보관 기간 설정
  - **미성년자**: 13세(미국)/16세(EU) 미만은 보호자 동의 흐름 필수 (댄스 학원 주 고객층)
  - GDPR/CCPA 데이터 내보내기·삭제 요청 처리
  - AI 학습 활용은 **명시적 옵트인**만 허용
- **성능**: 영상 첫 프레임 < 1.5초 (CDN + HLS), 모바일 3G에서도 피드백 텍스트는 즉시 표시
- **접근성**: WCAG 2.1 AA, 키보드 전체 조작, 자막(음성 노트 자동 전사)
